# Техническое задание — Dentaly CRM

> CRM-система для стоматологической клиники. Документ описывает, **что** должно
> быть реализовано. Эталон интерфейса — `index.html` (интерактивный мокап,
> разверните и кликайте). Модель данных — `schema.sql`. Архитектура и API —
> `BACKEND_PLAN.md`.

- **Заказчик / витрина:** сеть клиник «Smile Studio» (Алматы)
- **Продукт:** Dentaly CRM v4.2 (бренд Pllato)
- **Язык интерфейса:** русский
- **Валюта:** тенге (₸), формат `1 314 000 ₸`, locale `ru-RU`
- **Тип:** SPA (vanilla JS) + Cloudflare Workers API. Без билд-системы.

## 1. Роли и доступ

| Роль | Код | Что видит / может |
|------|-----|-------------------|
| Управляющий / владелец | `owner` / `manager` | Всё: финансы, аналитика, настройки, все клиники |
| Администратор | `admin` | Расписание, пациенты, запись, коммуникации, оплаты |
| Врач | `doctor` | Своё расписание, карты пациентов, зубные формулы, планы, протоколы |
| Ассистент | `assistant` | Расписание, карта пациента (чтение), склад-списание |
| Гигиенист | `hygienist` | Как врач, профиль гигиены |

- Мультиклиника: переключатель клиники в сайдбаре («Smile Studio ›»). Данные
  изолированы по `clinic_id`. Управляющий видит несколько клиник.
- Текущий пользователь в мокапе — **Платон Антонов · Управляющий**.

## 2. Общий каркас интерфейса

- **Сайдбар (236px, тёмный)**: бренд → переключатель клиники → навигация
  (две группы: «Работа», «Бизнес») → профиль пользователя снизу.
  - Группа **Работа**: Дашборд · Расписание (бейдж «14») · Пациенты · Лечение
  - Группа **Бизнес**: Финансы · Склад (бейдж «3» = позиций ниже минимума) ·
    Коммуникации · Аналитика
- **Топбар (60px)**: хлебные крошки · глобальный поиск (⌘K) · кнопки «+ запись»
  и «уведомления» (колокольчик с индикатором).
- **AI-ассистент**: плавающая кнопка справа снизу → выезжающая панель чата.
- **Cmd+K**: командная палитра (поиск пациентов, переход к разделам, команды).
- **Модальные окна**: новая запись, новый пациент, создание плана лечения,
  добавление визита/этапа, карточка записи.
- **Toast-уведомления**: на действия (создано/отправлено/удалено).

### Дизайн-система (зафиксирована в мокапе)
- Основной цвет `--primary:#0F766E` (бирюзовый), сайдбар `#0E1F1E`.
- Семантика: green/amber/red/blue/purple/gold для бейджей и статусов.
- Карточки `--r-lg:14px`, тени мягкие, KPI-плитки, таблицы `.tbl`, бейджи `.badge`.
- Кнопки 36px, клик-таргеты ≥44px на мобиле. Иконки — inline SVG.

## 3. Модули

### 3.1 Дашборд `/dashboard`
Стартовый экран управляющего. Содержит:
- Приветствие по времени суток + сводка дня (записей сегодня, загрузка кресел %).
- **4 KPI**: Выручка за месяц, Средний чек визита, Загрузка кресел, Новые пациенты
  (каждый — со стрелкой динамики к прошлому периоду).
- **График выручки** по дням (area-chart, переключатель 14Д/30Д/90Д).
- **Воронка пациентов**: Лиды → Запись → Визит → Согласован план → Оплата 1-го
  этапа → Повторный визит. Показ конверсии между этапами.
- **Тепловая карта** «загрузка врачей × дни недели».
- **«Сейчас в клинике» (Live)**: кто из пациентов в кресле, процедура, врач,
  кабинет, сколько минут идёт приём.
- **Топ врачей за месяц** (выручка, загрузка).
- **Виджет онлайн-записи**: превью встраиваемого виджета `smile-studio.kz`
  + счётчик записей через виджет.

### 3.2 Расписание `/schedule`
- Сетка «время × врачи» (столбцы — врачи, строки — слоты по 30 мин, 09:00–20:00).
- Вкладки дней недели (Пн–Сб). Цвет записи = категория процедуры.
- Запись показывает: пациента, процедуру, статус (точка), индикатор риска отмены (⚠).
- Клик по записи → модалка с деталями (пациент, процедура, стоимость, врач,
  кабинет, риск отмены + AI-рекомендация прозвонить, кнопки WhatsApp/Позвонить/
  Открыть карточку).
- Кнопка «Записать» → модалка новой записи (пациент, дата, время, врач, процедура).
- Статусы записи: `pending` (ждём подтверждения) · `confirmed` · `inchair`
  (в кресле) · `done` · `noshow` (не пришёл) · `cancelled`.

### 3.3 Пациенты `/patients`
- **Список** с фильтр-чипами по сегментам: Все · Активные · Спящие 6+ мес ·
  Должники · VIP · Новые (счётчики на каждом).
- Таблица: Пациент (аватар+тег) · Телефон · Врач · Последний визит · Визитов ·
  Баланс (красным если долг) · Источник · быстрые действия (позвонить, WhatsApp).
- Кнопка «Новый пациент» → модалка (фамилия, имя, телефон, дата рождения, источник).
- Сегменты вычисляются: `new` (1 визит / недавняя регистрация), `sleeping`
  (нет визита 6+ мес), `debtor` (balance<0), `vip` (по LTV/лояльности), `active`.

#### Карточка пациента `/patient/:id` — 7 вкладок
**Шапка**: аватар, имя+тег+предупреждение (аллергия), возраст, телефон, email,
источник, «клиент с …», статистика (визитов / сумма / баланс), кнопки
«Записать» и «WhatsApp».

1. **Обзор** — хронология взаимодействий (звонки, визиты, оплаты, согласование
   плана, сообщения, NPS); блок «Надиктовать протокол визита» (AI-Whisper);
   карточка лояльности; быстрые факты (лечащий врач, аллергии, способ оплаты,
   согласие на маркетинг, язык, семейные связи); скоринг рисков (кольцевой
   прогресс % риска); следующая запись.
2. **Зубная формула** ⭐ — интерактивная карта зубов (FDI 11–48, верхняя/нижняя
   челюсть). Каждый зуб = состояние (здоров/кариес/пломба/коронка/имплант/
   удалён/эндо) с детализацией по поверхностям (M/D/O/V/L). Клик по зубу →
   панель с историей зуба + кнопка «+ Процедура». Легенда + сводка
   (кариес/пломбы/коронки/импланты/удалены).
3. **План лечения** — см. 3.4 (та же сущность, что и модуль «Лечение»).
4. **Визиты** — таблица всех визитов (дата, врач, процедура, зубы, длит-сть,
   стоимость, статус).
5. **Финансы** — плитки (оплачено за всё время, активный план, средний чек) +
   история операций (дата, операция, способ, сумма, статус).
6. **Файлы и снимки** — КТ (.dicom), прицельные снимки (.jpg), цифровые слепки
   (.stl 3Shape), планы/ИДС/договоры (.pdf), фото до/после, гарантийные
   сертификаты. Хранятся в R2.
7. **Коммуникации** — переписка по каналам WhatsApp / Telegram / SMS
   (переключатель каналов, пузыри сообщений, поле ввода, прикрепление файла),
   список каналов пациента, быстрые шаблоны.

### 3.4 Лечение / Планы лечения `/treatment` и вкладка плана
Богатая модель: **план → череда визитов → набор процедур (этапов)**.
- **Список планов** (`/treatment`): согласованные планы должников, прогресс
  (этапов done/всего), следующий шаг, врач, сумма; KPI (согласовано планов,
  средний чек плана, конверсия в план).
- **Карточка плана** (вкладка пациента):
  - **Hero**: кольцевой прогресс (оплачено %), визитов done/всего, процедур
    done/всего, дата согласования; «К оплате всего» (со скидкой) / «Оплачено» /
    «Остаток»; кнопки «Добавить визит», «PDF клиенту».
  - **3 варианта лечения**: Эконом / Стандарт / Премиум (название, описание,
    сумма, срок). Активный вариант передаётся пациенту на согласование.
    Переключение варианта — клик по карточке.
  - **Этапы по визитам**: карточки визитов (дата, название, врач, длит-сть,
    кол-во процедур, сумма, статус). Внутри — строки этапов (зуб, процедура,
    статус, цена). Незавершённый визит можно «Записать», этап — удалить.
  - **График платежей** + остаток к доплате.
  - **Документы**: ИДС, договор, гарантийные талоны (подписаны электронно).
  - **AI-рекомендация**: например, предложить Kaspi-рассрочку 0/0/12 на остаток
    с прогнозом вероятности согласования; кнопка «Отправить пациенту».
- **Создание плана** (модалка): название → вариант → добавление этапов
  (зуб + процедура из прайса) → скидка % → «Сохранить черновик» /
  «Согласовать с пациентом». Статусы: `draft` → `agreed` → `in_progress` →
  `completed` / `cancelled`.

### 3.5 Финансы `/finance`
- KPI: Выручка / план (% выполнения), Дебиторская задолженность (сумма + кол-во
  должников), Маржинальность.
- **Структура выручки по направлениям** (пирог: имплантация, ортопедия, терапия,
  ортодонтия, эндодонтия, гигиена).
- **Должники**: список (пациент, сколько дней долгу, телефон, сумма) → клик ведёт
  в финансы пациента.
- **Прайс-лист**: таблица процедур (название, категория, цена, длит-сть, маржа)
  с фильтром по категории и редактированием.
- Кнопки «Принять оплату», «Экспорт».
- Способы оплаты: Kaspi QR, Kaspi Red (рассрочка 0/0/N), Карта VISA, Наличные.

### 3.6 Склад `/inventory`
- KPI: Стоимость склада, Ниже минимума, Скоро истекут (до 60 дней), Списано за месяц.
- Таблица позиций: название, категория, остаток (бар + цвет: красный если ниже
  минимума), минимум, срок годности, стоимость остатка. Кнопка «Заказать» для
  позиций ниже минимума.
- Категории: Анестезия, Расходники, Пломбировочные, Имплантация, Инструменты,
  СИЗ, Цементы, Эндодонтия, Дезинфекция, Ортодонтия.
- Движения: поступление (приход), списание (расход, в т.ч. автосписание на визит),
  инвентаризация (корректировка).
- Бейдж «3» в сайдбаре = число позиций ниже минимума.

### 3.7 Коммуникации `/comms`
- KPI: Отправлено за месяц, Доставлено %, Подтверждений записей %, NPS-ответов.
- **Каналы**: WhatsApp (Cloud API), Telegram (Bot `@smile_studio_bot`),
  SMS (шлюз Mobizon) — статистика отправлено/доставлено по каждому.
- **Активные диалоги**: список переписок (пациент, последнее сообщение, время,
  непрочитанные, иконка канала) → клик открывает вкладку коммуникаций пациента.
- **Автоматизации** (8 сценариев, вкл/выкл тумблером): подтверждение записи,
  напоминание за 2 часа, запрос NPS, реактивация спящих, день рождения,
  профосмотр через 6 мес, должникам (пауза), реферальная программа.
- 24 шаблона сообщений с плейсхолдерами.

### 3.8 Аналитика `/analytics`
- KPI: LTV пациента, CAC, LTV/CAC, Retention 12 мес.
- **Источники привлечения**: Instagram, Рекомендации, 2GIS, Google, Сайт, TikTok
  — доля, число пациентов, ROI.
- **Когортный анализ удержания**: heatmap % возврата по месяцам после 1-го визита.
- **Производительность врачей**: загрузка, пациентов, конверсия в план, NPS,
  выработка.
- Обновление каждые 5 минут, экспорт, выбор периода.

### 3.9 Настройки `/settings`
Плитки разделов: Клиника (реквизиты, адрес, расписание) · Сотрудники · Кресла и
кабинеты · Прайс-лист · Шаблоны документов (ИДС, договоры) · Интеграции (Kaspi,
WhatsApp Business, 1С Бухгалтерия, Bitrix24) · Программа лояльности (3 уровня,
1 балл = 10 ₸) · Уведомления (SMS Mobizon, WhatsApp Cloud API) · Безопасность
(2FA, журнал действий, ролевая модель).

### 3.10 AI-ассистент «Dentaly AI»
- Бренд: «Помощник врача · GPT-4 + DentNet».
- Чат-панель с быстрыми подсказками: «Кто из пациентов в группе риска?»,
  «Анализ снимка КТ», «Составить протокол по жалобе», «Кто давно не приходил?».
- Сценарии (в проде — на реальной базе): группа риска отмены, анализ КТ-снимка,
  структурированный протокол по жалобе, кандидаты на реактивацию по LTV.
- **Надиктовка протокола** (Whisper): запись голоса врача → расшифровка →
  структурированный протокол (жалобы → объективно → диагноз → план → назначения).
- **Скоринг рисков**: модель оценивает риск отмены/ухода пациента (0–100%),
  подсвечивает в расписании и карточке.

## 4. Сквозные сущности и бизнес-правила

- **Зубная формула**: нотация FDI (11–18, 21–28, 31–38, 41–48). Состояние зуба
  целиком (коронка/имплант/удалён/эндо) либо по поверхностям M/D/O/V/L
  (кариес/пломба/здоров). См. таблицы `teeth`, `tooth_history`.
- **Баланс пациента**: `balance < 0` → долг → тег `debtor`. Формируется из
  начислений (план/процедуры) минус оплаты.
- **Лояльность**: 3 уровня (Silver/Gold/Platinum), 1 балл = 10 ₸. Начисление за
  оплаты, бонусы (день рождения), списание.
- **Воронка/лиды**: lead → booked → visited → plan → paid → repeat. Источник лида
  и UTM сохраняются для аналитики ROI и CAC.
- **NPS**: опрос после визита (0–10), комментарий, влияет на рейтинг врача.
- **Документы**: ИДС и договоры генерируются из .docx-шаблонов (docxtemplater) →
  PDF (через сервис конвертации), подписываются электронно в личном кабинете.

Полная модель данных с типами и связями — в **`schema.sql`** (демо-данные —
**`seed.sql`**).

## 6. Нефункциональные требования

- **Производительность**: первичная загрузка SPA < 1.5 c; ответы API p95 < 300 мс.
- **Real-time**: статусы записей «в кресле», новые сообщения, уведомления —
  через WebSocket (Durable Objects).
- **Безопасность**: JWT (TTL 48 ч), bcrypt, ролевая модель, rate-limit логина,
  CORS allowlist, журнал действий (audit), 2FA для управляющего. Доступ к файлам
  пациента (КТ, снимки, ИДС) — только авторизованным (R2 через подписанные ссылки).
- **Приватность**: медданные пациентов; разграничение по `clinic_id`; экспорт
  и удаление по запросу.
- **Адаптив**: десктоп-first (рабочее место администратора/врача), планшет в
  кресле; клик-таргеты ≥44px.
- **Локализация**: ru. Тенге, формат дат `ru-RU`, часовой пояс Asia/Almaty (UTC+5).

## 7. Этапы внедрения (предложение)

1. **MVP-ядро**: auth + роли, пациенты (список/карточка/обзор), расписание,
   прайс-лист, запись. Демо-данные из `seed.sql`.
2. **Клиника**: зубная формула, планы лечения (визиты/этапы/варианты), визиты,
   финансы пациента, оплаты.
3. **Бизнес**: финансы (дебиторка, структура выручки), склад + автосписание,
   аналитика, дашборд.
4. **Коммуникации**: WhatsApp/Telegram/SMS, шаблоны, автоматизации, виджет записи.
5. **AI**: скоринг рисков, надиктовка протокола (Whisper), ассистент на базе.
6. **Документы**: ИДС/договоры (.docx→PDF), электронная подпись, гарантии.
